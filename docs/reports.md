# 测试结果报告

每轮运行结束自动生成 `summary.txt` 和 `summary.md`。前者适合终端查看，后者提供按suite划分的表格及相对路径链接。后台运行时，报告路径写入该轮 `worker.log`。

## 内容结构

1. 运行编号、方案、时间、整体状态与执行用例计数。
2. 按suite的状态概览，区分可展示样本、无效样本和未测量项目。
3. 各suite的执行结果、正确性、关键指标和日志链接。
4. 未进入本次计划的配置，以及节点原生报告归档状态。

报告中的 `C01` 等标记是本轮用例的简写，末尾列出与原始用例ID的对应关系。模型会话按精度、性能子任务分别展示，不重复增加执行用例总数。子任务没有结果时，父会话即使完成，也不能作为子任务测量完成的依据。

## 指标与边界

| Suite | 摘要内容 |
| --- | --- |
| RCCL | 各通信项的消息大小、模式、algbw、busbw、延迟；单位为GB/s、us |
| PCIe | 同一配置的五类路径数、Avg及Peak带宽范围；单位GB/s |
| memory / operators / MIGraphX / DeepEP / Mooncake | 原生指标名、数值、单位及统计口径，不从名称猜测或转换未知单位 |
| e2e_acc | 模型、实际评分题数、shot、分数、输出上限、记录的thinking开关及判定策略 |
| e2e_perf：LLM | 输入/输出目标长度、并发、轮次、输出吞吐、TTFT/TPOT均值、成功/失败请求数 |
| e2e_perf：Wan | 视频配置及Pixel、Denoise、单步、Decode、API耗时，单位秒 |

摘要较长时只展示前12条指标，完整数据写入每节链接的 `report-details/suite-*.csv`。明细保留原始参数、工作负载、节点、轮次、模拟标记和原生统计口径；未展示的形状、rank或P99并未被丢弃。不同配置、模型、节点和轮次不在新版摘要中合并求均值。原有 `summary.json` 分组统计契约保持不变。

`completed` 是执行状态，不代表数值正确性或性能达标；`duration_reached` 是计划时间结束，不等于原生压力循环自然完成。已取消或失败的用例即使保留部分有效数据，也必须连同执行状态阅读。未知/未测量数据不替换为0，失败正确性或无效样本不进入性能表。

报告不解析日志推断故障根因，也不自动确认独占条件。结构化原因缺失时显示退出码、阶段、清理状态和日志位置；没有资源守卫记录时，不把外部任务归为取消原因。

## 保留的数据

`metrics.csv`、`summary.json`、`e2e.csv/md` 以及原始 `state.json`、`results.jsonl`、分用例日志和归档报告继续保留。新版报告仅是这些记录的阅读视图；不修改执行逻辑、模型命令、正确性阈值或原生测试接口。

```bash
bash bench.sh report /实际结果目录/RUN_ID
```

该命令可为历史结果重新生成报告，不启动HCU任务。报告展示异常时，工具输出明确警告并回退逐条文本汇总；原始测量数据仍可查看。
